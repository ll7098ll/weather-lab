# 개발 문서

## 실행 구조

프레임워크와 번들러 없이 브라우저의 ES 모듈을 사용합니다. `dist/`가 실제 편집 소스이자 정적 호스팅 대상입니다. 현재 패키지 버전은 `1.1.0`이며 npm 의존성은 없습니다.

```text
index.html → app.js → 실험 계산·장면·렌더링 모듈
                  ↘ localStorage / CSV 내보내기
           ↘ import map → vendor/three.module.js

server.mjs → dist/ 파일을 로컬 HTTP로 제공
tests/*.test.mjs → dist/의 모듈을 직접 검증
```

## 모듈별 역할

| 파일 | 역할 |
| --- | --- |
| `dist/index.html` | 페이지 구조, 실험 탭, 안내창, Three.js import map |
| `dist/style.css` | 화면 스타일, 작은 화면 배치, 컨트롤과 노트 표현 |
| `dist/app.js` | 앱 상태, UI 이벤트, 장면 구성, 기록 관리와 CSV 출력 |
| `dist/physics.mjs` | 이슬점·응결·기압·비열·공기 밀도 계산 |
| `dist/air-particles.mjs` | 밀도 비교용 점 수와 운동률, 입자 시간 누적 |
| `dist/airflow.mjs` | 순환 곡선과 흐름 입자·이동 자취 |
| `dist/motion.mjs` | 흐름 속도 보간, 이동 거리와 입자 미세 운동 |
| `dist/condensation-scene.mjs` | 응결 과정 재생과 물방울·안개·구름 장면 |
| `dist/render-runtime.mjs` | 필요할 때만 렌더링하는 루프, 품질별 픽셀 제한 |
| `dist/scene-optimization.mjs` | 정적 메쉬 묶음 처리와 동적 대상 제외 |
| `dist/vendor/` | Three.js r170, OrbitControls, BufferGeometryUtils, MIT 라이선스 |
| `server.mjs` | `127.0.0.1`에 바인딩하는 로컬 확인용 정적 서버 |

`server.mjs`는 `PORT` 환경 변수 또는 기본값 4173을 사용합니다. `dist/` 안의 파일을 제공하며 경로가 루트 밖으로 벗어나면 거부합니다. 로컬 확인용이며 외부 호스팅에서는 `dist/`를 직접 배포합니다.

## 개발 방법

1. Node.js 24.x 환경에서 `npm start`를 실행합니다.
2. 변경할 파일을 `dist/`에서 직접 수정합니다.
3. 브라우저를 새로 고쳐 결과를 확인합니다. 자동 새로고침 기능은 없습니다.
4. 관련 테스트를 실행하고 최종 확인으로 `npm test`를 실행합니다.
5. UI나 모형이 바뀌면 사용법·계산 모형·화면 예시도 함께 갱신합니다.

개별 테스트 예시:

```sh
node --test tests/physics.test.mjs
```

현재는 빌드·린트 스크립트가 없습니다. 설치할 의존성이 없고 lockfile도 없으므로 `npm ci`를 실행할 필요가 없습니다.

## 브라우저 저장 데이터

| 키 | 값 | 용도 |
| --- | --- | --- |
| `weather-lab-notes-v1` | 기록 객체 배열의 JSON | 관찰 노트 최대 40개 |
| `weather-lab-quality` | `clear` 또는 기본 `light` | 화면 품질 설정 |

기록 객체는 다음 필드를 가집니다.

```json
{
  "title": "이슬 실험",
  "detail": "처음 습도 70% · 잎 온도 10.0℃ · 이슬 생성",
  "note": "잎 표면이 차가워지자 물방울이 생겼다.",
  "time": "2026-10-29T00:00:00.000Z"
}
```

`time`은 기록 시각의 UTC ISO 문자열입니다. 기록을 읽을 때 배열과 필수 문자열 필드를 확인하고 최근 40개로 제한합니다. 메모를 HTML에 표시할 때 이스케이프하고, CSV에서는 따옴표를 이스케이프하며 수식 시작 문자 앞에 작은따옴표를 붙입니다. 앱에 사용자 계정·DB·CSV 가져오기·클라우드 동기화는 구현되어 있지 않습니다.

## 렌더링과 품질

두 품질 모두 목표 프레임 속도는 60fps이며 기기 성능에 따라 실제 속도는 달라집니다.

| 품질 | 픽셀 비율 상한 | 총 픽셀 예산 | 그림자 |
| --- | --- | --- | --- |
| `light` | 1 | 1,100,000 | 끔 |
| `clear` | 1.5 | 2,200,000 | 켬 |

실제 픽셀 비율은 기기 비율·품질별 상한·화면 크기의 픽셀 예산 중 작은 값을 따릅니다. 페이지가 숨겨지거나 관찰 영역이 화면 밖으로 나가면 루프를 쉬게 합니다. 돌아왔을 때 숨겨진 시간을 한꺼번에 재생하지 않습니다. 애니메이션이 없고 다시 그릴 필요도 없을 때는 프레임 예약을 멈춥니다.

입자는 `InstancedMesh`를 이용하고, 정적 지형은 가능한 범위에서 묶어 그리기 호출 수를 줄입니다. 바뀌는 대상과 투명 대상은 정적 묶음에서 제외합니다.

## 검증 범위

| 테스트 파일 | 확인하는 내용 |
| --- | --- |
| `physics.test.mjs` | 응결 임계 조건, 기압 방향, 비열 비율, 밀도 관계 |
| `air-particles.test.mjs` | 기압·온도별 점 수와 운동, 강조 모드, 시간 연속성 |
| `airflow.test.mjs` | 순환 방향, 바람 세기, 실제 표시 위치 변화 |
| `motion.test.mjs` | 세기·방향 변경의 연속성, 프레임 속도 독립성 |
| `condensation-scene.test.mjs` | 생성·사라짐, 물방울 위치, 구름 상승과 팽창 |
| `render-runtime.test.mjs` | 렌더링 예약, 경과 시간, 숨김 처리, 픽셀 예산 |
| `scene-optimization.test.mjs` | 메쉬 묶음의 경계 유지와 동적 대상 제외 |

패키지 준비 시 Node.js 24.14.0 / npm 11.9.0에서 기존 테스트 30개를 통과했습니다. 이 테스트는 브라우저 전체 동작이나 실제 기기의 WebGL 성능을 자동 검증하는 E2E 테스트는 아닙니다.

UI를 바꾼 경우에는 세 실험 전환, 생성·사라짐 재생, 기압 방향 반전, 가열·냉각 그래프, 노트 저장·CSV 출력, 작은 화면과 키보드 조작을 브라우저에서 추가 확인합니다.
